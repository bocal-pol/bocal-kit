# ADR 0066 — api-finder: a static snapshot rather than a runtime clone

**Date:** 2026-10-02
**Status:** Accepted

## Decision

The `api-finder` skill ships a frozen excerpt of a public-APIs catalog in
`skills/api-finder/references/public-apis.md`, rather than cloning or querying the source repo on
every invocation.

## Reason

The source file (a README, roughly 280 KB, ~2,500 lines) fits entirely into a level-3 resource
(loaded on demand, never at the skill's trigger time) once cleaned of promotional noise. A clone
or a network call on every invocation adds a dependency and latency for content that doesn't change
from one invocation to the next within the same working session.

## Consequences

- The catalog goes stale silently: a new category or API added to the source repo after this ADR's
  date won't appear until the snapshot is regenerated by hand.
- `SKILL.md` explicitly warns to check the source repo if a category seems thin for a given need,
  rather than concluding no matching API exists.
- No automatic refresh mechanism at this stage: worth reconsidering if the catalog proves stale in
  real use (moving then to an on-demand `WebFetch` or a cached clone under `~/.claude/`, rejected
  here as a first solution for a need not yet proven).

## Alternatives considered

- **A shallow clone cached under `~/.claude/`, refreshed if older than 7 days**: adds cache
  management and a network dependency for a marginal gain until real usage shows that freshness is
  an actual problem.
- **`WebFetch` on every invocation**: systematic latency and a network dependency, for content that
  changes on a monthly scale, not a session scale.
