# .NET Developer — Clean Architecture

`[Activated: .NET Developer]`

Strict Clean Architecture: Domain → Application → Infrastructure → Api. `Result<T>` for all returns.
`[Injectable]` for DI auto-registration. Static mappers + LINQ projections.

> **Absolute rule**: every method returns `Task<Result<T>>` or `Task<Result>` · never an uncaught
> exception outside the `SafeExecute` pattern · `[Injectable]` on every service/repository · mappers
> as separate static classes · LINQ projections as `Expression<Func<>>` to avoid materialization ·
> `DbEntity` suffix on EF entities · `DbEnum` suffix on enums · XML comments on every public member.

## ✓ Validators — FluentValidation on RequestDTOs

Validation lives **at the request boundary**. `AbstractValidator<TRequestDto>` for each DTO.

- **Mandatory location**:
  - `src/Application/DTOs/Requests/*Validator.cs` (one per RequestDto)
- **Critical elements**:
  - Base validations (NotEmpty, MaxLength, IsEnum, Range)
  - FK validations (MustAsync + repository check)
  - Custom validations (complex business logic)
  - Localized messages
- **Registration**: `services.AddValidatorsFromAssemblies(...)` in DI
- **Automatic**: `[ApiController]` validates automatically → 400 + detailed errors on failure
- **Full example** → see the `dto-architect` skill (CreateRequestRequestDtoValidator)

## 📊 Projections — LINQ Expression DbEntity → ResponseDto

Projections convert **at the SQL level** for performance (no full entity load).

- **Mandatory location**:
  - `src/Application/Mappers/*Mapper.cs` (static class with
    `Expression<Func<TDbEntity, TResponseDto>>`)
- **Critical elements**:
  - `Expression<Func<>>` projection for SQL-level Select()
  - Enums `.ToString()` in the projection
  - **Never** include raw navigations (FK relations)
  - Minimal columns only
  - `.Compile()` for in-memory execution if needed
- **Usage**: `.Select(Mapper.ToDtoProjection).ToListAsync()` in the repository
- **Alternative (in-memory)**: map after Include() if navigations are required
- **Full example** → see the `dto-architect` skill (RequestMapper.ToDtoProjection)

## 🔧 Services & Interfaces — Business orchestration

Services orchestrate business logic: **validated RequestDto → Repository → Transformations →
ResponseDto**. Never put business logic in the controller or the repository.

### Service implementation

```csharp
// Application/Services/RequestService.cs
[Injectable]
public class RequestService : IRequestService
{
    // ──── Injections ────
    private readonly IUnitOfWork _unitOfWork;
    private readonly IEmailService _emailService;
    private readonly ICurrentUserService _currentUserService;
    private readonly IAiAssistantService _aiAssistantService;
    private readonly IRequestBusinessRuleService _br;
    private readonly ITemplateRenderService _templateRender;
    private readonly IPdfService _pdfService;
    
    public RequestService(
        ILogger<RequestService> logger,
        ICurrentRequestService currentRequest,
        IUnitOfWork unitOfWork,
        IEmailService emailService,
        ICurrentUserService currentUserService,
        IAiAssistantService aiAssistantService,
        IRequestBusinessRuleService br,
        ITemplateRenderService templateRender,
        IPdfService pdfService)
        : base(logger, unitOfWork.RequestRepository)
    {
        _unitOfWork = unitOfWork;
        _emailService = emailService;
        _currentUserService = currentUserService;
        _aiAssistantService = aiAssistantService;
        _br = br;
        _templateRender = templateRender;
        _pdfService = pdfService;
    }
    
    /// <summary>
    /// CREATE — Validate → Map → Persist → Enqueue → Return
    /// </summary>
    public Task<Result<RequestReadDto>> CreateRequest(RequestWriteDto dto) =>
        Result<RequestReadDto>.SafeExecute(async () =>
        {
            var entity = RequestMappers.MapToDbEntity(dto, _currentUserService.ZoneId);
            var created = await _unitOfWork.RequestRepository.Create(entity)
                .ThrowIfNotSuccess();
            
            await _requestCreatedQueue.EnqueueAsync(created.Id);
            
            return await GetRequest(created.Id);
        });
    
    /// <summary>
    /// ASSIGN — Atomic locking + Idempotence
    /// </summary>
    public Task<Result<RequestReadDto>> AssignRequest(Guid id) =>
        Result<RequestReadDto>.SafeExecute(async () =>
        {
            await _unitOfWork.RequestRepository
                .AcquireRequest(id, _currentUserService.UserId)
                .ThrowIfNotSuccess();
            
            return await GetRequest(id);
        });
    
    /// <summary>
    /// UPDATE — Validate state → Apply → Track → Optional enqueue
    /// </summary>
    public Task<Result<RequestReadDto>> UpdateRequest(Guid id, RequestWriteDto dto) =>
        Result<RequestReadDto>.SafeExecute(async () =>
        {
            var entity = await _unitOfWork.RequestRepository.FindById(id)
                .ThrowIfNotSuccess();
            
            _br.EnsureRequestCanBeUpdated(entity).ThrowIfNotSuccess();
            
            RequestMappers.ApplyToDbEntity(dto, entity);
            
            await _unitOfWork.RequestHistoryRepository.Add(
                new RequestHistoryDbEntity { 
                    Action = RequestHistoryActionDbEnum.Updated, 
                    RequestId = id 
                });
            
            await _unitOfWork.RequestRepository.UpdateAndSave(entity)
                .ThrowIfNotSuccess();
            
            if (dto.IsUrgent)
                await _requestCreatedQueue.EnqueueAsync(id);
            
            return await GetRequest(id);
        });
    
    /// <summary>
    /// AI ORCHESTRATION — AI service call → Persist → Enqueue next
    /// </summary>
    public Task<Result> SetGeneratedAIContent(Guid id, CancellationToken ct = default) =>
        Result.SafeExecute(async () =>
        {
            var entity = await _unitOfWork.RequestRepository
                .FindRequestWithAiDetails(id).ThrowIfNotSuccess();
            
            var aiResult = await _aiAssistantService.GenerateSummaryAsync(entity, ct)
                .ThrowIfNotSuccess();
            
            entity.Summary.Content = aiResult.Content;
            entity.Summary.Status = RequestGenerationStatusDbEnum.Done;
            
            await _unitOfWork.RequestRepository.UpdateAndSave(entity)
                .ThrowIfNotSuccess();
            
            if (entity.IsUrgent)
                await _requestAiQueue.EnqueueAsync(id);
            
            return Result.Success;
        });
    
    private Task<Result<RequestReadDto>> GetRequest(Guid id) =>
        GetEntityById(id, RequestProjections.ProjectToRequestReadDto);
}
```

### Controller — calls the service, never the repository directly

```csharp
[ApiController]
[Route("api/[controller]")]
public class RequestController
{
    public RequestController(private IRequestService _service) {}
    
    [HttpPost]
    public async Task<IActionResult> Create([FromBody] RequestWriteDto dto)
    {
        // Service handles: validation (DTO), persistence, queue, return DTO
        var result = await _service.CreateRequest(dto);
        return result.IsSuccess ? CreatedAtAction(nameof(Get), new { id = result.Data.Id }, result.Data)
            : BadRequest(result.GetError());
    }
}
```

**Key patterns**:
- **Result<T>** wrapper — success/error monad
- **SafeExecute** — automatic catch-all
- **UnitOfWork.ThrowIfNotSuccess()** — short-circuit on error
- **Atomic transactions** (via UnitOfWork.SaveChangesAsync)
- Idempotence — check state before action
- History tracking — every mutation recorded
- **[Injectable]** — DI auto-registration
- **Service receives an interface injection**, never a direct DbContext implementation

### Where does business logic live?

| Logic | Home | Never in |
|---------|----------|-------------|
| Base validations (NotEmpty, MaxLength, IsEnum) | **FluentValidation** | ❌ Service |
| Complex rules (state machine, dependencies) | **BusinessRuleService** or Aggregate | ❌ Controller |
| Entity ↔ DTO transformation | **Mapper** (static class) | ❌ Service |
| Persistence access | **Repository** (interface) | ❌ Direct service (DbContext) |
| Orchestration (service calls + persistence) | **Service** (here) | ✅ Correct |
| Multi-step transactions | **Service** (UnitOfWork) | ❌ Repository |
| Domain business behavior | **Aggregate root** | ❌ Raw service |

## 🔄 Mappers — Entity ↔ DTO conversion

Static mappers convert at the appropriate time (SQL-level or in-memory).

- **Mandatory location**:
  - `src/Application/Mappers/*Mapper.cs` (static class)
- **Critical elements**:
  - LINQ projections for SQL-level conversions (repository)
  - In-memory mappers if navigations/relations are required
  - Bidirectional: Entity → DTO, RequestDto → Entity
  - Enums: string ↔ enum conversion
  - Null-safety: check nullability before conversion
- **Full example** → see the `dto-architect` skill (RequestMapper with ToDtoProjection +
  ToDetailDto + FromRequestDto)

## 📦 Repositories — Persistence abstraction

Repositories **abstract data access** — services call the repository, never DbContext directly.
Interface + implementation pattern.

### Full .NET structure

- **Mandatory location**:
  - `src/Shared/Application/IBaseServiceRepository.cs` (base CRUD interface)
  - `src/<Domain>/Application/I<Entity>Repository.cs` (specialized business interface)
  - `src/<Domain>/Infrastructure/Repositories/<Entity>Repository.cs` (`[Injectable]`
    implementation)
- **Hierarchy**:
  - `IBaseServiceRepository<TEntity>` (CRUD: Get, Find, GetCount, Create, Update, Delete, etc.)
  - `I<Entity>Repository : IBaseServiceRepository<TEntity>` (specialized business queries)
  - `<Entity>Repository : PostGresRepository<TContext, TEntity>, I<Entity>Repository`
    (implementation)
- **Required**:
  - Atomic transactions (`BeginTransactionAsync`) for multi-updates
  - Eager loading via `.Include()` (no N+1)
  - Bulk updates `.ExecuteUpdateAsync()` for performance
  - `Expression<Func<>>` projections for Entity → DTO at the DB level
  - Idempotence on sensitive requests (acquire, assign, supervise)
  - `Result<T>` pattern for error handling
  - `[Injectable]` on the implementation class
- **Service calls the repository**: never DbContext directly
- **Full example** → see the `dto-architect` skill (IBaseServiceRepository + IRequestRepository +
  RequestRepository)

## ⚙️ EF Core Configuration — Constraints & Performance

**Mandatory**: each DbEntity has its own `IEntityTypeConfiguration<T>` class defining indexes,
lengths, conversions, relations, cascade delete. This guarantees migrations create the right
structure **and** the right DB constraints.

- **Mandatory location**:
  - `src/Infrastructure/Persistence/Configurations/` → `*Configuration.cs` (one per DbEntity)
  - Applied in `DbContext.OnModelCreating()` via `modelBuilder.ApplyConfiguration(new ...())`
- **Critical elements**:
  - **Indexes**: Status, Category, CreatedDate, foreign keys (filtering/sorting performance)
  - **MaxLength**: every string field (integrity + perf)
  - **Enum conversion**: `<int>` (serialize in DB, not string)
  - **Default values**: in DB, not in the app (RequestCategoryDbEnum.None)
  - **Collation**: for specific text search/sort needs
  - **Relationships**: HasOne/WithMany/HasForeignKey + cascade delete on required one-to-one
  - **Ignore**: unmapped computed properties (AllRequestLinks)
- **Full example** → see the `dto-architect` skill (RequestConfiguration)
- **Migration**: `dotnet ef migrations add CreateRequest` generates SQL **with indexes and
  constraints** if the configuration is correct.
- **Verification**: re-read the generated `.sql` file, check indexes and defaults before pushing.

## 🗂️ DbEntity — Infrastructure layer (persistence)

`DbEntity` classes are **internal to the Infrastructure layer**. Never in an API response. Shared
interfaces (`IHasDateTime`, `IHasAuditUser`, `IDeadLine`, etc.) avoid duplication.

- **Mandatory structure**:
  - `src/Infrastructure/Persistence/Entities/` → `*DbEntity.cs` (EF Core aware, **mandatory**
    suffix)
  - `src/Infrastructure/Persistence/Interfaces/` → `IHasDateTime.cs`, `IHasAuditUser.cs`, etc.
    (shared across entities)
  - `src/Infrastructure/Persistence/Configurations/` → `*DbEntityConfiguration.cs` (Fluent API)
- **Minimal rules**:
  - Mandatory inheritance from a `KeyDbEntity` base (`public Guid Id`).
  - **Strict** `DbEntity` suffix (never `Entity`, never `Model`).
  - Shared properties via interfaces: `IHasDateTime`, `IHasAuditUser`, `ICode`, `IDeadLine`,
    `IAssignation`, `ISupervision`, etc.
  - Collections: `ICollection<T> = []`, never a List that publicly exposes `Add()`.
  - Navigations: `public virtual AddressDbEntity Address { get; set; }`, commented with
    `/// <summary>`.
  - **No business logic** in the DbEntity — it's a pure ORM container.
  - Enums: `DbEnum` suffix (e.g. `RequestStatusDbEnum`, distinct from business enums).
  - Null-safety: `public string Title { get; set; } = string.Empty;`.
- **Full detail (interfaces, RequestDbEntity example, structure)** → see the `dto-architect` skill.

## 📦 DTOs — delegated to `dto-architect`

Every public API method returns a `Result<T>` where **T is a DTO or a primitive type**, never a
`*DbEntity`.

- **Mandatory location**:
  - `src/Application/DTOs/Requests/` → `Create<Feature>RequestDto.cs` +
    `Create<Feature>RequestDtoValidator.cs` (FluentValidation)
  - `src/Application/DTOs/Responses/` → `<Feature>ResponseDto.cs`
  - `src/Application/Mappers/` → `<Feature>Mapper.cs` (static class +
    `Expression<Func<TDbEntity, TResponseDto>> ToDtoProjection`)
- **Minimal rules**:
  - Strict `RequestDto` / `ResponseDto` suffix (never `UserDto`)
  - Immutable C# `record`s — no mutable classes
  - Validation via `AbstractValidator<TRequestDto>` in the same folder as the DTO
  - LINQ projection (`Select(UserMapper.ToDtoProjection)`) on every EF Core query that returns a
    DTO — never `.ToList()` then in-memory mapping
  - **`Ok(userDbEntity)` FORBIDDEN** — must call `UserMapper.ToDto()`. A DbEntity is never in JSON.
  - Never include raw navigations in a DTO (e.g. `Source`, `Address`, `Requester`) — use explicit
    IDs or nested DTOs.
  - Sensitive fields never in a `ResponseDto` (password hash, refresh token, internal data)
- **When to create a DTO**: every minimal API/controller endpoint, every CQRS Command/Query, every
  MediatR handler.
- **Full detail (mapping, versioning, advanced projections)** → see the `dto-architect` skill.

### Phase 4 — EF Core Configuration

> ⚠️ **Configuration rule**: one class per entity in `Infrastructure/Database/Configurations/` ·
> Fluent API exclusively (no DataAnnotations) · index on filtered columns · `search_ci_ai` collation
> on searchable text fields · `HasConversion<int>()` on enums
>
> ⚠️ **Data isolation (`security-architect`, table-by-table discipline)**: any entity carrying an
> ownership column (`ZoneId`, `TenantId`, `UserId`...) declares a global **Query Filter** in its
> configuration — never a `.Where()` added manually to each repository query, which gets forgotten
> on the first ad hoc query. `builder.HasQueryFilter(e => e.ZoneId == _currentZoneId)` (an
> `ICurrentZoneAccessor` service injected into the configuration class). Full reference:
> `skills/security-architect/SKILL.md`, "Row-level data isolation" section.

```csharp
using Microsoft.EntityFrameworkCore;
using Microsoft.EntityFrameworkCore.Metadata.Builders;
using Company.Backend.[Service].Domain.DbEntities;
using Company.Backend.Shared.Infrastructure.Database;

namespace Company.Backend.[Service].Infrastructure.Database.Configurations;

internal class [Feature]Configuration : IEntityTypeConfiguration<[Feature]DbEntity>
{
    public void Configure(EntityTypeBuilder<[Feature]DbEntity> builder)
    {
        // Indexes
        builder.HasIndex(p => p.Status);
        builder.HasIndex(p => p.ZoneId);
        builder.HasIndex(p => p.CreatedDate);

        // Enum → int storage
        builder.Property(p => p.Status)
            .HasConversion<int>()
            .HasDefaultValue([Feature]StatusDbEnum.Pending);

        // Text columns — collation for CI/AI search
        builder.Property(x => x.Title)
            .HasMaxLength(LengthTextConfig.TitleTextString)
            .UseCollation(RequestDbContext.CollationName);

        builder.Property(x => x.Description)
            .HasColumnType("text")
            .HasMaxLength(LengthTextConfig.BigTextString);

        // Relationships
        builder.HasMany(x => x.Histories)
            .WithOne(h => h.[Feature])
            .HasForeignKey(h => h.[Feature]Id)
            .OnDelete(DeleteBehavior.Cascade);
    }
}
```

### Phase 5 — Mapper + Projection

> ⚠️ **Mapper rule**: static classes · `Func<WriteDto, DbEntity>` for creation (factory pattern) ·
> separate `Apply(WriteDto, DbEntity)` method for updates · **never** AutoMapper

> ⚠️ **Projection rule**: `Expression<Func<DbEntity, ReadDto>>` compiled into the LINQ query · never
> `.ToList()` before `.Select()` · include only the fields needed by the DTO

```csharp

namespace Company.Backend.[Service].Application.Mappers;

/// <summary>Mapping functions for [Feature] — Write → DbEntity.</summary>
public static class [Feature]Mappers
{

    public static Func<[Feature]WriteDto, [Feature]DbEntity> MapTo[Feature]DbEntity(Guid zoneId) =>
        dto => new [Feature]DbEntity
        {
            Title = dto.Title,
            Description = dto.Description,
            Status = [Feature]StatusDbEnum.Pending,
            ZoneId = zoneId,
            Histories =
            [
                new [Feature]HistoryDbEntity
                {
                    Action = [Feature]HistoryActionDbEnum.[Feature]Created,
                }
            ],
        };

    /// <summary>Applicator for UpdateEntity — mutates existing entity.</summary>
    public static [Feature]DbEntity ApplyTo[Feature]DbEntity(
        [Feature]WriteDto dto,
        [Feature]DbEntity entity)
    {
        entity.Title = dto.Title;
        entity.Description = dto.Description;
        return entity;
    }
}
```

```csharp
using Company.Backend.[Service].Application.Infrastructure.Repositories;
using Company.Backend.[Service].Domain.DbEntities;
using Company.Backend.[Service].Infrastructure.Database.Contexts;
using Company.Backend.Shared.App;
using Company.Backend.Shared.Infrastructure.Repositories;
using Company.Backend.Shared.Patterns.Result;

namespace Company.Backend.[Service].Infrastructure.Repositories;

/// <summary>Repository for [Feature] entities.</summary>
[Injectable]
public class [Feature]Repository(
    [Service]DbContext context
) : PostGresRepository<[Service]DbContext, [Feature]DbEntity>,
    I[Feature]Repository
{
    /// <summary>Acquire [feature] atomically — prevents double assignment.</summary>
    public async Task<Result> Acquire[Feature](Guid featureId, Guid userId)
    {
        await using var transaction = await Context.Database.BeginTransactionAsync();

        var updated = await DbSet
            .Where(f => f.Id == featureId && f.AssignedUserId == null)
            .ExecuteUpdateAsync(setter => setter
                .SetProperty(p => p.AssignedUserId, userId)
                .SetProperty(p => p.AssignedDate, DateTime.UtcNow));

        if (updated == 1)
        {
            Context.Set<[Feature]HistoryDbEntity>().Add(new [Feature]HistoryDbEntity
            {
                [Feature]Id = featureId,
                Action = [Feature]HistoryActionDbEnum.Acquired,
                UserId = userId,
            });

            await Context.SaveChangesAsync();
            await transaction.CommitAsync();

            return Result.Success;
        }

        if (await DbSet.AnyAsync(f => f.Id == featureId && f.AssignedUserId == userId))
            return Result.Success;

        return Result.Already.WithReason("Already acquired by another user");
    }
}
```

```csharp
            [Feature]Projections.ProjectTo[Feature]ReadDto

        return new Result<[Feature]ReadDto>(feature);
    }

        Guid id,

        => await UpdateEntity(
            id,
            dto,
            [Feature]Mappers.ApplyTo[Feature]DbEntity,
            [Feature]Projections.ProjectTo[Feature]ReadDto
        );
```
